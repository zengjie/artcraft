# 内部使用 ArtCraft + fal Proxy：审计结论与迁移路线

研究日期：2026-10-07。审计版本：fork `21a4385738`；上游 `main` 为 `3e5793b6934b51536606720e5d56bcfd1fe7cc2d`，通过 `git ls-remote upstream refs/heads/main` 实时核对，目前正是本 fork 的基础提交。本报告是迁移设计，**不是全功能验收报告，也不表示下述改造已经实施**。

## 结论

建议采用 **保留上游客户端 + 新增独立 FalProxy provider + 独立 Proxy 服务**。先做随客户端编译的扩展模块，再争取把通用 provider 扩展接口贡献给上游。不建议继续把 ArtCraft 官方 API 全局替换成 Proxy，也不建议一开始投入通用热加载插件系统。

目前不能确认所有 AIGC 功能都能经 Proxy 执行。已确认的真实闭环是飞书认证、FLUX Schnell 文生图以及用户生成的 Kling 视频与详情播放；音频、网格、图像编辑等的适配代码或模拟测试，不等于真实桌面流程已经验收。详见 [功能覆盖审计](aigc-coverage-audit.md)。

## 许可证与需要纠正的现状

官方文档自称 **ArtCraft License (WIP)** 和 fair source，并明确尚非 OSI 开源许可证。条款禁止出售软件、利用代码开发竞争业务/产品、移除社区/捐赠/付费模型服务，以及未经允许用名称、标识或吉祥物推广自己的业务。[官方许可证（审计提交）](https://github.com/storytold/artcraft/blob/3e5793b6934b51536606720e5d56bcfd1fe7cc2d/LICENSE.md)

条款中的关键对象包含 “community, donation links, or paid model services”。因此，恢复几个链接、保留未执行的源代码，不能替代保留实际可用的官方付费模型服务。以下是当前技术审计结论，并非作者出具的法律解释：

| 当前改动                         | 实际影响                              | 应做的修复                                       |
|----------------------------------|---------------------------------------|--------------------------------------------------|
| 顶栏移除了积分、购买和升级入口     | 官方商业入口被替换                    | 恢复原入口，新增独立的 fal Proxy 状态/入口         |
| BillingSettingsPane 只显示 fal    | 官方订阅、充值、管理入口不再呈现      | 原版计费面板保留，fal 计费另设区域                |
| 飞书替代原版登录弹窗              | 无法通过原登录入口获得官方账号会话    | 官方登录保持；飞书只连接组织 Proxy                |
| 官方 API host 全局指向 Proxy      | 官方账号、订阅和模型请求进入替代服务  | 两个独立客户端、origin、凭据及错误状态            |
| 所有请求被标为 Artcraft provider  | 实际 provider 与展示、任务归属不一致 | 独立 FalProxy 标识，恢复原路由判断                |
| 模型目录只保留 Proxy 返回值       | 官方模型服务不可选                    | 按 provider 聚合能力，不覆盖官方目录              |
| Proxy 返回零积分、空订阅          | 仅为旧协议兼容，不是真实官方账单      | 只用于原型过渡；正式架构不得把它当官方余额或订阅 |

依据：[顶栏](../../frontend/apps/artcraft/app/src/components/signaled/TopBar/TopBar.tsx)、[计费面板](../../frontend/libs/components/settings-modal/src/lib/panes/BillingSettingsPane.tsx)、[登录弹窗](../../frontend/libs/components/login-modal/src/lib/login-modal.tsx)、[API host](../../crates/desktop/artcraft/src/core/state/app_env_configs/app_env_configs.rs)、[强制路由](../../crates/desktop/artcraft/src/core/commands/generate/omni/request.rs)、[目录合并](../../frontend/libs/model-list/src/lib/loader/buildModelsFromListing.ts)、[Proxy 兼容接口](../../proxy/src/server.mjs)。原版 UI 可从上述上游基础提交逐项恢复，不必重写。

此前为了简化原型而删除商业入口、替代官方服务的实现方向需要纠正。当前已交付的测试包仍有这些问题；本次研究不会把它描述为已经符合完整保留要求的内部发行版。

### 企业内部使用需要澄清什么

许可证允许修改、编译与使用的文字写的是 “private personal purposes”，同时又表达支持创意工作室和企业的意愿。它并未用严谨定义明确覆盖企业内部部署、员工二进制分发及独立插件发布。**不能仅凭“不对外销售”保证企业内部使用已获得充分授权。** 建议取得维护者书面确认，保留其解释记录；这不妨碍继续研究和修复技术问题。[官方许可证](https://github.com/storytold/artcraft/blob/3e5793b6934b51536606720e5d56bcfd1fe7cc2d/LICENSE.md)

可向维护者询问的具体范围（这里只准备内容，不代发消息）：

> 我们希望将 ArtCraft 用作公司内部创作工具，不向外部销售或提供竞争性 AI 创作服务。计划增加使用飞书认证的内部 fal Proxy，并将其设置为组织默认 provider；保留原有社区、支持、订阅、充值、官方账号和付费模型服务，员工可主动选择官方服务。请确认企业内部部署、向员工分发修改后的安装包，以及公开贡献通用 provider 扩展接口是否被当前许可证允许；也请说明第三方适配器的独立发布及命名要求。

持续支持可以落实为官方服务采购、上游公开的支持渠道、可独立审查的缺陷修复与测试贡献；实际采购、付款和对外联络由组织另行执行。

## 产品入口：默认方便，但不取代官方

推荐的交互是设计提案，尚未实现：

- 设置中的两个独立连接：**ArtCraft 官方账号**、**组织 fal Proxy（飞书）**。连接一个不使另一个退出，也不把飞书身份伪装为官方账号。
- 组织预置 Proxy 地址；飞书登录成功后，支持的能力默认优先使用 FalProxy，避免每次选择。保留清晰的 provider 切换，并记住用户显式选择。
- 模型选择器聚合官方和 Proxy 能力，显示实际 provider；相同模型名称不能证明参数或价格相同，能力按 provider 分开。
- 顶栏保留原版支持/升级/积分入口；追加简短的 Proxy 连接状态。设置中的原版计费区域保留，fal 用量和组织管理另设区域。
- 缺失能力显示“此 Proxy 暂不支持”，提供主动选择官方服务的入口。禁止请求失败后静默改走另一计费账号、降低模型质量或忽略关键参数。
- 飞书会话、官方会话、任务、上传素材与下载索引均须带 provider/instance 归属。跨 provider 复用素材应明确上传到所选服务，不能直接复用对方的 media token。
- 官方积分只呈现官方真实结果；fal 费用由组织账号承担，不折算或伪装成 ArtCraft 积分。

## 实施顺序与验收门槛

| 阶段 | 交付内容                                                | 通过条件                                                          |
|------|---------------------------------------------------------|-------------------------------------------------------------------|
| P0   | 分离官方与 Proxy 身份/路由，恢复原商业及模型入口          | 两种账号独立登录退出；官方入口调用官方服务；Proxy 凭据不外发        |
| P1   | 最小 provider 扩展接口 + 编译时 FalProxy 模块             | 官方核心 UI 少量接线；禁用扩展时恢复上游行为；能独立测试扩展        |
| P2   | 按功能覆盖矩阵补适配和完整操作流程                        | 每个声称支持的功能通过真实桌面端到端测试；缺失能力不误导为可用      |
| P3   | 组织部署、打包与权限/用量管理                            | 服务密钥不入客户端；会话/素材隔离；持久化、恢复与费用上限得到验证   |
| P4   | 上游同步 CI、小型补丁序列、提交通用扩展接口的提案         | 临时分支上重放补丁、构建及回归通过，才能更新内部发行分支            |

P0 应先于扩大内部使用。不要把“恢复按钮”单独当作 P0 完成。P2 应按用户工作流验收，不按模型目录数量验收。API 单次成功也不能替代上传、轮询、重启恢复、媒体播放、导出和编辑器回填的验证。

不要承诺“永远无冲突 rebase”。能建立的是持续验证、冲突显性化和可回退的升级流程。当前上游与 fork 基础相同，暂时不存在需要处理的上游增量；无需为了研究重写已发布分支历史。详细接口边界、补丁分层和 CI 方案见 [扩展机制研究](fal-proxy-extension-strategy.md)。

## 已执行的验证

- `npm test --prefix proxy`：9/9 通过，均为本地模拟测试，不产生 fal 费用。受限沙箱首次运行因禁止监听 localhost 失败；在允许本机监听的环境重跑后通过。
- 无网络调用 `buildInput` 的探针：FLUX、Nano Banana、Kling、Stable Audio、Hunyuan 有输入 adapter；`flux_2_lora_angles`、`qwen_edit_2511_angles`、`flux_pro_1p1`、`marble_0p1_plus` 被返回 400。这个结果仅证明当前 allowlist/输入映射行为。
- 本轮未追加真实付费生成；此前已确认的真实测试与本轮源码/模拟检查分开记录。

## 本轮完成与未完成

本轮完成许可证核对、上游版本核对、源码覆盖审计和迁移设计；不运行大批付费模型，也不替组织联系维护者或购买服务。**没有在本轮实施双 provider 架构、恢复完整官方商业服务或认证所有 AIGC 功能。** 当前测试包仍用于原型验证，不应被作为本报告目标已经实现的证据。
